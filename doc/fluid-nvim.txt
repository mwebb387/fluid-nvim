INTRO                                                      *fluid-nvim-intro*

Fluid-nvim is a framework for expressive and "fluid" Neovim configuration
using fluent syntax. It provides a modular approach to Neovim configuration
with a chainable API that makes configuration files more readable and 
maintainable.

Key features:
  • Fluent, chainable API for configuration
  • Modular plugin architecture with opt-in modules  
  • Automatic plugin management and installation
  • Dependency resolution between modules
  • Clean separation of concerns


==============================================================================
INSTALLATION                                        *fluid-nvim-installation*

1. Clone fluid-nvim to your Neovim configuration directory: >

    git clone https://github.com/mwebb387/fluid-nvim \
      ~/.config/nvim/pack/config/opt/fluid

2. Add fluid-nvim to your init.lua: >

    vim.cmd.packadd 'fluid'
    require('fluid'):setup(function(f, nvim)
      -- Your configuration here
    end)

USAGE                                                        *fluid-nvim-usage*

Basic usage involves calling modules and options using fluid's chainable API: >

    local fluid = require('fluid')
    fluid:setup(function(f, nvim)
      f:telescope()
        :lsp()
        :treesitter()

      nvim('hidden', 'number')
        -- Set Neovim options
        :set('tabstop', 4)
        :set('shiftwidth', 4)
        -- Other Neovim settings...
    end)

Modules can be configured with options: >

    f:lsp():options('icons', 'server_management')
      :telescope()

Options can also be passed directly to the module call: >

    f:lsp('icons', 'server_management')
      :telescope()

Table arguments are deep-merged into the module's plugin configuration, and
can be mixed freely with string options in the same call: >

    f:telescope({ defaults = { prompt_prefix = '> ' } })
      :treesitter('highlight', { indent = { enable = true } })

The fluent syntax supports multiple operators:
  • Function call: `f:module()`
  • Modulo: `f % 'module`'
  • Division: `f / 'module`'
  • Addition for options: `f + 'option'  
  • Multiplication for options: `f * 'option'`

NOTE: Lua syntax does not allow for using function calls and operators cleanly
so the cleanest way to use the other operators is to use operators only
without function calls. 

    f /'lsp' +'icons' +'server_management'
      /'telescope'

CONFIGURATION                                        *fluid-nvim-configuration*

Fluid-nvim uses a two-phase setup:

1. **Init Phase**: Modules declare dependencies and plugins
2. **Setup Phase**: Modules configure their functionality

Each module can define:
  • `init()` - Called during the init phase to set up dependencies
  • `setup(deps)` - Called after plugins are installed with resolved deps
  • `options` - Available configuration options  
  • `dependencies` - Required modules or packages

Fluid API                                                    *fluid-nvim-api*

The fluid API provides methods for configuring Neovim and managing modules.

                                                              *fluid:setup()*
fluid:setup({config})
    Initialize fluid-nvim with the given configuration function or table.
    
    Parameters: ~
        {config} (function|table) Configuration function, or a table with
                 an `init` function, that receives the fluid instance and
                 `nvim` module.

                                                             *fluid:module()*
fluid:module({name})
    Load and configure a module by name.
    
    Parameters: ~
        {name} (string) The module name to load.
        
    Returns: ~
        fluid instance for chaining

                                                           *fluid:{module}()*
fluid:{module}({...})
    Load and configure a module by calling its name directly on the fluid
    instance, e.g. `f:telescope()`. Arguments are optional: string arguments
    are added as options for the module (as with |fluid:options()|), and
    table arguments are deep-merged into the module's plugin configuration.
    Strings and tables can be mixed in a single call.

    Parameters: ~
        {...} (string|table) Optional option names and/or config overrides.

    Returns: ~
        fluid instance for chaining

                                                             *fluid:option()*
fluid:option({name})
    Add an option to the current module.
    
    Parameters: ~
        {name} (string) The option name to enable.
        
    Returns: ~
        fluid instance for chaining

                                                            *fluid:options()*
fluid:options({...})
    Add multiple options to the current module.
    
    Parameters: ~
        {...} (string) Variable number of option names.
        
    Returns: ~
        fluid instance for chaining

Fluid Module API                                       *fluid-nvim-module-api*

Modules in fluid-nvim are enhanced with additional methods through a metatable
that provides dependency management and option checking capabilities. When a
module is loaded, it automatically receives these methods.

Module Structure ~

Each module should be structured as a Lua table that can include:

    • `init(fluid)` - Called during init phase to declare dependencies
    • `setup(deps)` - Called after plugin installation with resolved dependencies
    • `options` - Table of available configuration options
    • `dependencies` - Table of module dependencies (auto-managed)

Module Methods ~

These methods are automatically available to all fluid modules via metatable:

                                                               *module:has()*
module:has({option})
    Check if a specific option is enabled for this module. These are options
    added by the user via `fluid:option()` or `fluid:options()`.
    
    Parameters: ~
        {option} (string) The option name to check.
        
    Returns: ~
        (boolean) true if option is enabled, false otherwise.
        
    Example: >
        function M:setup(deps)
          if self:has('icons') then
            -- Configure icons
          end
        end
<

                                                             *module:use()*
module:use({spec})
    The single entry point for registering plugins and declaring
    dependencies. The meaning is determined by the shape of {spec}:

    • string containing `/` — a plugin source; an `owner/repo` shorthand
      is expanded to the GitHub URL, full URLs (any protocol), scp-style
      `git@` addresses, and local paths are used as-is.
    • string without `/` — a Lua require path declared as a dependency,
      resolved and passed to `setup(deps)` under its own name (rename
      with `.as()`).
    • table with a `src` field — a native |vim.pack| plugin spec
      ({src=..., version=..., name=...}), passed through.
    • list table — a batch of plugin specs (strings or spec tables);
      batch registrations cannot be refined with chain methods.

    Returns a chainable refinement API. Chain methods must be called with
    a `.`, not `:`. Module methods remain reachable from the chain with `:`.

    Parameters: ~
        {spec} (string|table) Plugin source, require path, vim.pack spec,
               or list of plugin specs.

    Returns: ~
        Refinement API with `at()`, `providing()`, and `as()` methods.

    Example: >
        function M:init(fluid)
          self
            -- Plugin only
            :use('kylechui/nvim-surround')

            -- Plugin pinned to a branch, exposing two require paths
            :use('nvim-telescope/telescope.nvim')
              .providing('telescope')
              .providing('telescope.actions').as('actions')

            -- Dependency only (no plugin): a require path has no '/'
            :use('fluid.nvim').as('nvim')

            -- Batch install (not refinable)
            :use{
              'hrsh7th/cmp-buffer',
              { src = 'folke/tokyonight.nvim', version = 'v4.11.0' },
            }
        end
<

                                                            *use-chain:at()*
use-chain.at({version})
    Pin the plugin registered by the preceding `use()` to a version — a
    branch name, tag, or |vim.version.range()| — mapped to the vim.pack
    spec's `version` field. Errors when the preceding `use()` declared a
    dependency rather than a plugin.

    Example: >
        self:use('ThePrimeagen/harpoon').at('harpoon2')
          .providing('harpoon')
<

                                                     *use-chain:providing()*
use-chain.providing({path})
    Declare that the plugin registered by the preceding `use()` provides a
    require-able Lua module, exposing it in the `deps` table passed to
    `setup()`. May be called multiple times for one plugin. The dependency
    key defaults to {path}; rename it with `.as()`.

    Parameters: ~
        {path} (string) Lua require path provided by the plugin.

                                                            *use-chain:as()*
use-chain.as({name})
    Rename the most recent dependency — either the require path passed to
    `use()` directly, or the last `.providing()` — so it appears in the
    `deps` table under {name}.

    Parameters: ~
        {name} (string) The alias used as the key in `deps`.

Module Lifecycle ~

1. **Creation**: Module is loaded via `require('fluid.modules.name')`
2. **Enhancement**: Metatable is applied, adding API methods
3. **Init Phase**: `init(fluid)` called to declare dependencies and plugins
4. **Plugin Installation**: All declared plugins are installed
5. **Setup Phase**: `setup(deps)` called with resolved dependencies

Example Module ~
>
    local M = {}

    function M:init(fluid)
      -- Declare plugins, exposing require paths as dependencies
      self
        :use('nvim-telescope/telescope.nvim')
          .providing('telescope')

        -- Add plugins without named dependencies
        :use('nvim-tree/nvim-web-devicons')
    end
    
    function M:setup(deps)
      local telescope = deps.telescope
      
      telescope.setup({
        defaults = {
          -- Configure based on enabled options
          preview = { enable = self:has('preview') }
        }
      })
    end
    
    return M
<
